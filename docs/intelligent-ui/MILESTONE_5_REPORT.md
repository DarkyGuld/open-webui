Branch: `intelligent-ui-foundation`. Status: **complete** for the layout-primitive increment.
Zero new dependencies.

## Architecture change: single root → recursive tree

Before M5, Intelligent UI was a single root component. M5 introduces **recursive layout
composition**, which is the foundation for "arbitrary native layouts":

```
OpenUI library (catalog.ts)         containers have `children` unions of component refs
   ↓ toJSONSchema()
lang-core parser                    parses `root = Stack([g1, t1])` etc. (references/hoisting)
   ↓
engines/openui.ts  mapNode()        recursively maps ElementNode → canonical UINode tree
   ↓
schema.ts (recursive z.lazy)        validates the whole tree + node/depth/children limits
   ↓
NodeRenderer.svelte (svelte:self)   recursively renders native components
   ↓
native Open WebUI components
```

- **Catalog** (`catalog.ts`) is now the OpenUI library itself (single source): leaves + containers
  with `children` unions; the prompt is generated from it.
- **Canonical schema** (`schema.ts`) is a separate recursive contract (`z.lazy`) kept in sync by
  tests.
- **Renderer** (`NodeRenderer.svelte`) renders leaves (separate files) and containers inline,
  recursing via `<svelte:self>` (no circular imports).

## Limitations

- This M5 increment covers **layout composition + badge/divider**. The other families
  (tabs/accordion/list/steps, chart, form/inputs, image/gallery/code/progress/timeline) are the
  next increments of M5.
- No logic/state layer yet (M6): expressions, conditionals, loops, reactive state.
- Streaming still activates on the closed fence (M7).
- `comparison` items are not independently addressable as children yet (they are a leaf with an
  internal list) — fine for now.

## Readiness for M6

Ready. The recursive tree + registry + dispatcher are exactly what the logic layer needs: M6 wires
lang-core's `createStore`/`evaluate` so container/leaf props can be expressions and children can be
generated by `@Each`/ternary — **without a parallel engine**.
